# Recipe creator: idea, formula and personality

Implemented 12 November 2026. Optional short introduction (180 characters), full description, multi-select flavour profiles, explicit steep days, own-photo upload and personal notebook. The existing version notes remain public-to-recipe-viewers mixing/version notes; community comments remain on the saved detail page.

Short/long descriptions, profiles, steep time and normalized photo are stored with the recipe version in recipe_stories. Blank steep is NULL (Not set); zero is Shake & vape. Existing versions and imported notes remain unchanged. The private notebook is keyed by recipe AND current user and never joins library/discovery output. It is personal, not part of a published version.

Photos accept JPEG, PNG and WebP, limited to 5 MB/20 megapixels, EXIF orientation corrected, centre-cropped to 1200×675, re-encoded to WebP without source metadata. Invalid files are rejected while retaining text/ingredient input. Photo delivery uses the recipe account/visibility gates on every request, with private no-store caching. Images live in SQLite so existing database backups include them. Editing inherits the previous image unless replaced or explicitly removed; historical versions retain their own image. Users must reselect an image after reopening a draft or a failed save.

The live preview uses textContent. Short introductions/photos also appear on library and discovery cards. Browser drafts are keyed by user and recipe/new, with explicit restore/discard, preserved percentages and calculator settings, local-storage failure feedback, unload warning, and clearing only after a confirmed successful save redirects to the saved recipe. Drafts are device/browser-local, not cross-device synced; images are not stored in localStorage. Private notebook text is included in the local draft on this device. Mobile has a preview/settings jump link.

No automatic steep suggestion, flavour-testing notebook, notifications or guided-mix logic changes. Those remain deferred in issue #21. Future batch timers must snapshot the chosen version's steep days and distinguish unknown from zero.

Validation: six new integration tests cover round-trip/versioning, private note isolation, invalid-input preservation, photo conversion/access/inheritance/removal, invalid-image rejection and unique form fields/scoped draft keys. Combined builder/usage/discovery/dashboard run: 34 passed and one known baseline failure. A jsdom smoke check exercises escaped preview text, blank versus zero steep, autosave and exact percentage/ID restore; existing usage JavaScript tests remain green. One pre-existing Old Goat private-visibility test fails with 302 instead of expected 200 (previously reproduced on unchanged main). Final live desktop/mobile visual and upload checks follow deployment.
